This project looks at how security teams measure and report the business value of their work. I use Design Science Research: I build a framework, show it on synthetic cases, and evaluate it without participants. The evaluation checks the framework against its requirements, compares it with existing frameworks, and tests it on public material. I collect no data from people. The study does not assume or test any specific security role.

## Design propositions

I argue these from literature and public evidence. I do not test them with participants. RQ3 is exploratory and has no expected answer.

- **P1:** Value is "realized" only when the beneficiary confirms it. Self-reported value from the security team is not credible on its own.
- **P2:** The binding constraint is translation and validation with business owners, not measurement technique.
- **P3:** Realized value reporting (backward-looking, beneficiary-validated) complements protection-level governance such as outcome-driven metrics and protection-level agreements (forward-looking, executive-agreed). It does not duplicate it.
