Project 002 examines how security organizations measure and communicate the realized business value they deliver. It follows a Design Science Research approach: the output is a framework that is built, demonstrated on synthetic cases, and evaluated without participants through requirements testing, comparative analysis against existing frameworks, and a test against public material. No data is collected from people. The study is role-neutral: it does not assume or test any specific security role.

## Design propositions

These are argued from literature and public evidence, not tested with participants. RQ3 is exploratory and has no expected answer.

- **P1:** Value is "realized" only when the beneficiary confirms it. Self-reported value from the security team is not credible on its own.
- **P2:** The binding constraint is translation and validation with business owners, not measurement technique.
- **P3:** Realized value reporting (backward-looking, beneficiary-validated) complements protection-level governance such as outcome-driven metrics and protection-level agreements (forward-looking, executive-agreed). It does not duplicate it.
